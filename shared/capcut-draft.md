# 从规格编译剪映草稿

适用于已经完成分镜、配音及实际时码、并希望以 capcut-cli 建立可继续精剪的新草稿。先检查当前 CLI 的 `capcut describe --command compile`，确认版本与已安装剪映兼容；CLI 与原生应用是两个独立依赖。本流程不替代剪映原生预览、精剪与导出。

## 准备输入

1. 输出无连续解说字幕的画面底片、独立旁白与配乐 / 音效；画面时长、音频时长和字幕时间码用实际素材测量。章节、进度条、题印小地图若已合入底片，后续需改合成源重渲染；不要称它们是可单独调整的剪映图层。
2. 以当前 CLI schema 编写 JSON 规格，设置画布、帧率与轨道：底片为 video，旁白和配乐为各自 audio，每条解说字幕为独立 text item。记录各条的 start、duration、文字和样式；字幕样式在原生应用中校准。保存 SRT，字幕断句与音频实际对齐，而不是仅靠生成提示词估计。
3. 可恢复规格中的媒体路径优先相对于规格文件，保留原画、合成源、AI 片段、分轨声音和字体来源。用户选择整体可编辑时，不能用一条底片冒充逐镜、逐元素可编辑；根据需要建立更多原生轨道。

## 验证并生成

仓库脚本将规格内各轨 item 的相对 `path` 解析为相对于规格文件的绝对路径，检查素材存在，先调用 `capcut compile --check`，通过后才执行 `capcut compile --out`。它不覆盖已有输出、不修改原规格、不安装依赖，也不修改字体或打开剪映。

```bash
python3 scripts/compile_capcut.py /path/to/spec.json --out /path/to/new-draft --check-only
python3 scripts/compile_capcut.py /path/to/spec.json --out /path/to/new-draft
```

输出应为新的草稿目录；具体规格字段、模板与版本适配以当前 CLI schema 为准。可改用当前 CLI 原生命令，但仍先检查再生成。不要使用 `--force-write` 绕过保护。编辑已有草稿须先在原生应用关闭该项目、备份，并遵守 capcut-edit 的版本与并发保护。

按[字体与文字层级](typography.md)选用并核验字幕字体；命令成功或配置记录字体不代表每个字都实际可显示。支持的字幕字体设置、回退方法及打包条件随当前系统和工具而变，不依赖某台机器的绝对字体路径。输出项目里准确列出实际可编辑轨道。

## 验收和恢复

打开实际剪映草稿，检查字幕字号、配色、位置、代表性字形和音画同步；包含罕见人名时抽查对应时码。修复后重新预览及导出，必要时对最终视频取帧。完成原生导出、核对文件与完整解码；未试听或未检查的部分如实记录，导出不包含上传或发布授权。

需要可迁移工程时，打包原生草稿、规格、引用的媒体、字幕、字体选择 / 替代说明及所需恢复脚本。将规格中的素材路径改为相对包内位置，在解压后的新目录运行编译工具恢复，不覆盖现有草稿；核对每个引用都存在，确认实际目标系统的字体、CLI 与剪映兼容。原生草稿可能仍含旧机器的绝对路径，不要承诺直接复制即可恢复，也不要将私人路径和凭据写入公开案例。
